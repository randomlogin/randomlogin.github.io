3. What is kyoto?

it is a lightweight Rust library which implements BIP157.
The fact that it is a library means it does not have its own executable, but can rather be used in other pieces of
software (to add bitcoin node functionality).

3. How it works

In general terms kyoto connects to BIP157 compliant peers and retrieves:
1) chain headers 2) filter headers 3) filters themselves

Kyoto is split in "node" and "client" parts, node is responsible for the above. Client is meant to use in the business
logic of the user application. 

Client streams the events from the node, such as 
```
IndexedFilter
Header
Reorg
```
the user application checks `IndexedFilter` against watched data and then can perform further actions. 

For example invoke `get_block` or `brodacast`. However note, that kyoto does not have it's own mempool and cannot verify
that transaction was successfully broadcast until it is seen in a new block.

What kyoto does:

- manages peers
- participates in p2p gossip (however ignores some of the messages)
- broadcasts transactions
- maintains block header chain
- maintains filter header chain
- maintains compact block filters

- does not download (all) blocks
- does not have mempool
- does not maintain UTXO set
- does not store anything on disk (unless manually made to do so)
- does not have wallet functionality
- does not participate in block generation
